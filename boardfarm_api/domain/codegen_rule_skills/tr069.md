## TR-069 / ACS Parameter Management

### GPV Return Structure

`get_parameter_values` returns a list of dicts:
```python
[{"key": "Device.Path.Param", "value": "true", "type": "boolean"}, ...]
```

Access: `result[0]["value"]`. For path-based queries (`"Device.WiFi."`) the list contains all children — build a lookup dict if needed:
`{item["key"]: item["value"] for item in output}`

### SPV Calling Convention — The Format Trap

SPV takes a **list of single-key dicts**:
```python
set_parameter_values([{param: value}], acs=acs, board=board)
```

Multiple parameters:
```python
set_parameter_values([{param1: val1}, {param2: val2}], acs=acs, board=board)
```

**NOT** `{param: value}` (missing list), **NOT** `[{"name": param, "value": value}]` (wrong keys).

Returns `0` or `1` on success. On error raises `TR069FaultCode` with `exc.value.faultdict["spv_fault"][0]["FaultCode"]`.

For reverting in teardown with type preservation:
```python
[{"key": param, "value": original_value, "type": original[0]["type"]}]
```

### AddObject / DelObject

`add_object` returns an object with `.response` (bool) and `.instance_number` (str).
Build the new entry path: `f"{table_path}{instance_number}."` — then SPV its sub-parameters.

Track added entries in `bf_context` (e.g., a list) for cleanup in teardown via `del_object`.

### Parameter Attributes

`get_parameter_attributes` returns a dict with `"Notification"` key.
`set_parameter_attributes` takes a dict `{"Name": param, "Notification": "2"}` plus boolean flags `notification_change`, `access_change`.

Notification values: `0`=off, `1`=passive, `2`=active.

### Boolean Values Are Inconsistent

TR-069 booleans appear as strings `"true"/"false"`, integers `0/1`, or Python bools across different tests and parameters. Match whatever the captured original value's type is when reverting.

### Teardown Pattern

Capture original value BEFORE yield. Set `bf_context` flag after successful SPV. Revert in teardown using the captured original. For AddObject cleanup, `del_object` with the tracked entry path.

### No retry_on_exception

TR-069 RPCs are synchronous request-response. They don't need retry unless the test specifically polls for a value to change over time.

### CSV Parametrization

`read_data(__file__)` reads a companion CSV. First two columns are typically `_jira_id` and `_priority` (unused in test body, annotated `# noqa: ARG001,PT019`).
